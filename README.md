### BUG-002 — Некорректная цена в SEO-метатегах

При проверке метаданных, которую владелец магазина обозначил как проблемную область, обнаружил расхождение между ценой товара на витрине и значениями в `product:price:amount`, `description` и `og:description`.

Для товара «Жоу Гуй ААА» цена в метаданных составляла **31 800 ₽**, при этом на витрине были доступны **50 г за 1 590 ₽** и **100 г за 3 180 ₽**. Некорректная цена также была зафиксирована в поисковом сниппете.

Чтобы оценить масштаб проблемы, использовал вспомогательный Python-парсер, написанный с помощью LLM. Результаты сопоставлял с данными карточек товаров. На нескольких весовых позициях удалось подтвердить одинаковую закономерность; предполагаемая причина выделена отдельно от наблюдаемых фактов.

**Методы:** black-box, исследовательское тестирование, анализ HTML, проверка гипотез.

**Отчёт:** [BUG-002-seo-price-mismatch.pdf](./BUG-002-seo-price-mismatch.pdf)

### BUG-003 — Отсутствие валидации шага фасовки через API

В интерфейсе магазина весовые товары изменяются с шагом **50 г**, но при прямом обращении к `POST /cart/add/` можно передать количество, не кратное этому шагу.

Проверил поведение на двух весовых товарах через **Postman** и затем в интерфейсе корзины. В одном из сценариев переданный вес **316,75 г** отображался в корзине как **317 г**; во втором в корзине также зафиксировано некратное шагу количество **810 г**. При этом причина расхождения между отправленным и возвращённым количеством во втором сценарии не установлена.

Основной подтверждённый дефект — недостаточная серверная проверка допустимого шага фасовки. Возможные последствия для комплектации заказа описаны как риски, а не как уже произошедшие ошибки.

**Методы:** негативное API-тестирование, Postman, Chrome DevTools, сопоставление API и UI.

**Отчёт:** [BUG-003-cart-quantity-validation.pdf](./BUG-003-cart-quantity-validation.pdf)

## Инструменты и навыки, показанные в работах

- **Ручное тестирование:** исследовательские проверки, негативные сценарии, оформление баг-репортов.
- **API:** Postman, HTTP-запросы и ответы, анализ параметров и данных корзины.
- **Web:** Chrome DevTools, HTML-метаданные, проверка поведения интерфейса.
- **Анализ дефектов:** воспроизведение, проверка повторяемости, отделение фактов от гипотез, оценка потенциального влияния.
- **Вспомогательные инструменты:** Python-скрипт, созданный с помощью LLM, для сбора данных в исследовании BUG-002; Git и GitHub для хранения материалов.
