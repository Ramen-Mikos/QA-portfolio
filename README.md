# Практические проекты

## 1. Тестирование интернет-магазина «Сэр Пуэр»

**Объект тестирования:** действующий коммерческий интернет-магазин китайского чая.

**Типы тестирования:**
- Исследовательское
- Функциональное
- UI
- API
- Негативное

**Инструменты:** Chrome DevTools, Postman.

### Цель

Исследовать поведение интернет-магазина, проверить согласованность данных между интерфейсом и сервером, найти дефекты и задокументировать их.

### Обнаруженные дефекты

#### BUG-002 — Некорректная стоимость товара в SEO-метаданных

При исследовании страницы товара обнаружено расхождение между фактической стоимостью товара и ценой, указанной в структурированных данных страницы.

Значение цены в метаданных превышает фактическое в 10 раз.

**Что проверял:**
- Отображаемую стоимость товара.
- Данные страницы через Chrome DevTools.
- Соответствие структурированных данных фактической цене.
- Наличие аналогичного поведения на других товарах.

**Результат:** дефект задокументирован в баг-репорте.

[Посмотреть BUG-002](bug-reports/BUG-002.pdf)

#### BUG-003 — Обход ограничений выбора веса товара через API

В интерфейсе интернет-магазина предусмотрены ограничения на выбор веса товара.

При исследовании сетевых запросов обнаружена возможность передать значение веса, не соответствующее ограничениям интерфейса.

**Что проверял:**
- Поведение выбора веса в интерфейсе.
- Структуру запросов к серверу.
- Передачу нестандартных значений через API.
- Реакцию серверной части на некорректные данные.

**Результат:** обнаружено отсутствие необходимой серверной валидации передаваемого значения веса.

[Посмотреть BUG-003](bug-reports/BUG-003.pdf)

### Что удалось применить

- Анализ сетевых запросов через DevTools.
- Исследование REST API.
- Проверку клиентской и серверной валидации.
- Негативное тестирование.
- Оформление баг-репортов с шагами воспроизведения.
- Анализ причин возникновения дефектов.

## 2. SauceDemo — Тестирование авторизации

**Объект тестирования:** [SauceDemo](https://www.saucedemo.com/)

**Функциональность:** авторизация пользователя.

**Типы тестирования:**

- Негативное

### Цель

Проверить работу формы авторизации при вводе корректных и некорректных данных.

### Подготовленные тест-кейсы

| TC-001 | Успешная авторизация с валидными данными | Позитивный |

### Проверяемые аспекты
